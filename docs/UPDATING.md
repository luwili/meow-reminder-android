# Обновление с сохранением данных

## Для пользователя

Скачайте новый APK из Releases и откройте его на телефоне. Нажмите **«Обновить»**, а не удаляйте предыдущую версию. Пакет `ru.meow.reminder`, подпись и внутреннее хранилище остаются прежними. Все препараты, расписания, история, заметки, фразы и настройки сохраняются.

Перед обновлением полезно сделать JSON-экспорт через настройки. Экспорт не является обязательным этапом обычного обновления, но защищает от ошибок установки, потери телефона или удаления приложения.

При смене сертификата Android запрещает установку поверх существующей версии. Это относится к некоторым ранним CI-сборкам и сборкам из pull request: они могли использовать случайный debug-ключ. В таком случае сначала экспортируйте данные из старого приложения. Не соглашайтесь удалять его, пока не сохранили данные. Ни смена versionCode, ни переименование APK не обходят проверку подписи.

## Для разработки и выпусков

- Каждому новому опубликованному APK присваиваются **новые versionName и больший versionCode** в `app/build.gradle.kts`. 1.0.0 → code 1; 1.0.1 → code 2; 1.0.2 → code 3; 1.0.3 → code 4; 1.0.4 → code 5; 1.0.5 → code 6; 1.0.6 → code 7.
- `applicationId` не меняется.
- Используется постоянный сертификат SHA-256 `e34c11293f9b67a0e1b1203ea52658725682ea92420fad7838f1ffc783667f4b`.
- Тестовые Releases 1.0.0–1.0.6 используют один локальный debug-ключ. Для совместимости текущей линии его нельзя заменить произвольным новым release-ключом. Это не production/Play App Signing.
- GitHub Actions получает ключ из repository secret `MEOW_UPDATE_KEYSTORE_BASE64`, восстанавливает его вне проекта с правами 600 и проверяет сертификат собранного APK. В конце задания временный файл удаляется. При отсутствии секрета распространение push/ручной сборки останавливается, а не подписывается случайным ключом.
- Pull request не получает ключ обновлений. Его APK — только тестовый, не способ обновления установленного приложения.
- Схема Room сейчас version 1. Если она изменится, нужна явная миграция с сохранением записей. `fallbackToDestructiveMigration` не используется. DataStore не сбрасывается при обновлении; демонстрационные препараты не создаются заново.
- Ключи и пароли не добавляются в Git. Резервную копию ключа нужно хранить отдельно от исходников; потеря ключа лишит возможности подписывать совместимые обновления.

## Воспроизводимая проверка обновления

На отдельном чистом Android-эмуляторе:

```bash
python3 scripts/test-upgrade.py --adb /path/to/adb \
  --old /path/to/meow-reminder-1.0.0-debug.apk \
  --new /path/to/meow-reminder-1.0.2-debug.apk \
  --expected-version 1.0.2 --output /path/to/empty-test-output
```

Скрипт отказывается работать на физических телефонах. Он вводит свой препарат и заметку через настоящий интерфейс старой версии, меняет тему, устанавливает новый APK с `install -r` без удаления приложения и сравнивает все строки таблиц Room и настройки (кроме намеренно меняющегося списка последних фраз). Результат сохраняется в `result.json`. Для проверки новых миграций используйте чистый тестовый эмулятор, а не личные данные.
