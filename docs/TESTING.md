## Что проверяют тесты

**Чистая календарная логика:** однократное правило; несколько времён и дедупликация; каждые N дней/недель/месяцев; выбранные дни недели; 31-е и короткие месяцы; последний день; 29 февраля; бессрочные и конечные правила; счётчик отдельных приёмов; включительная дата окончания; завершённый курс; переход через полночь; DST gap и overlap; смена часового пояса; отсрочка; запрещённая доставка для подтверждённых/отключённых приёмов; стабильные ID; одновременные разные расписания; валидация; 108 уникальных фраз; JSON round trip.

**На Android:** Compose-навигация и сохранение заметки; реальная Room БД; аудит отметок; отмена дополнительных уведомлений; повторная материализация без дублей; отключение без потери истории; длинный текст (80 000 символов); объединение резервной копии; редактирование расписания; привязка отсрочки к одному приёму; защита от повторной доставки одного Broadcast-события.

## Не следует считать проверенным

Доставка в течение дней/недель на физическом телефоне, OEM-ограничения Samsung/Xiaomi и других прошивок, реальные аппаратные перезагрузки, длительный Doze и все комбинации разрешений Android 12–16. См. [контрольный список](DEVICE_CHECKLIST.md). Тесты состояния планировщика не доказывают абсолютную точность доставки системного будильника.

GitHub Actions отдельно запускает unit-тесты, lint, сборку и инструментальные тесты на API 35. Фактический статус конкретного запуска смотрите во вкладке Actions, а не выводите из локальных результатов.
